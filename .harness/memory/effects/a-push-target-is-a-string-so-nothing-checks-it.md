# E-063 — A push target is a string, so nothing checks it

**Link:** `apps/mobile/app` route tree → every `router.push` in `app/` and `src/`, the e2e journey
spec **Guard:** `gate:lint` (`verify-route-targets.mjs`) **Severity:** high **Feature:** F-145

---

## The gap

`router.push('/palettes')` is a **string**. It compiles whether or not the route exists, `lint`
sees a call with an argument, and the failure is a dead control on a screen somebody opens next
week.

expo-router *can* type these, through `.expo/types/router.d.ts` — but that file is generated by
the dev server rather than by the build, so on a clean checkout, which is what CI is, the types
are absent and the strings are unchecked again.

## Why it mattered here specifically

F-145 moved sixteen routes into a `(tabs)` group and rewrote thirteen push targets. **Nothing in
the repository could have told the difference between doing that correctly and doing it almost
correctly** — and "almost" means one dead button on one screen, which is exactly the class of
defect that gets reported months later as "this bit of the app doesn't work"
[[a-gate-must-model-what-renders-not-what-is-physically-correct]].

The gate was written before the conversion was finished and immediately caught a real one: a
`/palettes` target left over from before the move.

## What it understands, and where it stops

expo-router's rules, as far as they are needed:

- a **group** — a segment in parentheses — is not part of the URL, so `(tabs)/atlas` serves `/atlas`
- `index.tsx` is its directory
- `[slug].tsx` matches exactly one segment
- `_layout.tsx` is not a route

**A template literal becomes a wildcard.** `router.push(\`/atlas/${slug}\`)` is checked as
`/atlas/PARAM`, which asserts the *shape* exists and says nothing about whether that particular
slug does. That is the honest reading — the value is known only at runtime — and it is worth
knowing when reading a green run.

## What it does not do

It does not check that the destination is *reachable by a person* — only that the route exists.
A route with no control anywhere leading to it passes this and is the failure
[[a-tested-module-nobody-wired-up-passes-every-test-it-has]] describes. That is a different check
and nothing performs it.

It also cannot see navigation done any other way: `<Link href>`, `navigation.navigate`, or a
target assembled from a variable. Only `router.push` / `replace` / `navigate` with a literal
first argument. Every navigation in the product is one of those today.
