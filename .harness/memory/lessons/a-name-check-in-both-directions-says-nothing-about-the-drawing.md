# A name check in both directions says nothing about the drawing

**From F-228 (2026-09-21).** The icon registry was held to F-220's inventories in both directions —
every bound name has a glyph, every glyph is a bound name — with a decoy each way, plus the line
weight at four sizes, distinct silhouettes, declared fills and a hidden root. Thirteen gates were
green. **Nine of the sixty-five glyphs were still not what their mockup draws**, because `00` draws a
solid pencil, `02` and `03` a solid sun, `11` a solid bulb, `13` a solid eye, figure and scales — and
every one of them had been drawn as an outline.

A name test asks *does something exist under this name*. It cannot ask *is this the right drawing*,
and no amount of strengthening it in that direction will make it ask.

## What to do instead

- **Compare the artefact with its source, one by one, before claiming the set.** Every drawn instance
  of every name, beside the thing built for it, at a size a person can judge. F-228 built that sheet
  for the reconciliation of NAMES in increment 1 and did not build it again for the SHAPES.
- **Write down the comparison as evidence that outlives the session** — which element each drawing was
  made against, in the plan, and a measure of the two where one is possible (F-281).
- **Watch for the house style.** "Every glyph is an outline, in one ink" reads like restraint and is a
  design decision; the mockups had already made it differently, per element. Under golden rule 14 a
  consistency the images do not have is a departure, and an unrecorded departure is the finding.
- **One name drawn two ways is not a tie to break.** The contract's answer is to split the name and
  rebind the element — `close-circle`, `lock-solid`, `seal-check` and five more — so a name still
  means one shape. Picking the more common drawing silently loses the other screen's.
