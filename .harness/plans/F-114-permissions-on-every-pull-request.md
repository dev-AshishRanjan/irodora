## Intent

Gate 16 reads the built APK and is the only thing that catches a dependency shipping a
permission. It runs in `release.yml`, because there is no APK on a pull request — which is
correct, and means **the delay between introducing a permission and learning about it is a
tag**. F-043 added `expo-image-picker` and `RECORD_AUDIO`; five features closed before a signed
artefact said so.

Done: a permission introduced by configuration fails **the pull request that introduces it**, and
the check says plainly which half of the problem it cannot see.

## The file that makes this cheap

`expo prebuild` already runs inside gate 6 — `pnpm build` invokes it for `@irodora/mobile` — and
it writes `apps/mobile/android/app/src/main/AndroidManifest.xml`. That file is exactly what
`app.config.ts` and its plugins contribute, including which permissions carry
`tools:node="remove"`:

```xml
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.INTERNET" tools:node="remove"/>
<uses-permission android:name="android.permission.VIBRATE"/>
…seven more, all removed
```

So the check needs no Gradle, no JDK and no emulator — none of which this workstation has — and
runs on every CI run after gate 6.

## Approach

**Modelled on `verify-android-min-sdk.mjs`** (F-128): same zone, same shape — a script that reads
a prebuilt file, states what it cannot prove, and carries `--prove`. Nothing here is invented
where that file already made the choice.

**The declared list is derived, not copied.** `verify-apk.mjs` owns `EXPECTED_PERMISSIONS`, and
its own comment records why: the list *"used to be a workflow argument duplicated in two files,
and keeping two copies of a security-relevant set in agreement is not a thing to rely on a person
for"*. A second copy here would repeat exactly that mistake.

So the split is expressed the other way round:

```
config-contributed  =  EXPECTED_PERMISSIONS  −  MERGED_AT_GRADLE_TIME
```

`MERGED_AT_GRADLE_TIME` is the only new list, and it is **criterion 3 made executable**:
`USE_BIOMETRIC` and `USE_FINGERPRINT` come from `expo-local-authentication`'s library manifest,
and `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` is generated by AndroidX from the prebuild
template. None is in any file this check reads. Adding a permission to the APK's expectation
therefore changes what this expects, automatically, unless somebody declares it invisible — and
declaring it invisible is a deliberate act with a name.

**What it asserts:**

1. The manifest's **kept** permissions — those without `tools:node="remove"` — equal the
   config-contributed set, **in both directions**. An unexpected one is a capability nobody
   reviewed; a missing one is a feature that will fail on a device. Gate 16 already makes exactly
   this argument about the artefact.
2. Every permission the config **removes** is still removed, `INTERNET` named separately because
   it falsifies NFR-12 rather than being a review failure — the same split gate 16 draws.
3. The manifest exists at all. Absent, the check must fail loudly rather than pass vacuously:
   `prebuild` not having run is the state in which this reports nothing and looks green.

## Test plan

- **`--prove`, modelled on the min-sdk proof**, mutating a copy of the manifest in memory:
  - a planted `<uses-permission android:name="android.permission.INTERNET"/>` **without** the
    removal marker fires, and is reported as the NFR-12 finding rather than as "unexpected";
  - a planted `RECORD_AUDIO` without the marker fires as unexpected — **F-043's actual episode**,
    replayed;
  - removing `<uses-permission … CAMERA/>` fires as missing;
  - an absent manifest fires, rather than passing with nothing to check;
  - **the decoy: the real manifest is asserted GREEN before and after every plant.** A proof where
    everything is red cannot distinguish a working checker from one that fails on everything —
    `verify-apk.mjs`'s own header makes this point and it is not re-derived here.
- **Criterion 3 is asserted, not just written:** the check prints the `MERGED_AT_GRADLE_TIME`
  names on every run, so a reader of a green result sees what it did not look at.

## Verification

```
node scripts/verify-manifest-permissions.mjs
node scripts/verify-manifest-permissions.mjs --prove
node scripts/verify-apk.mjs --prove
node scripts/verify-gate-mirror.mjs
node scripts/verify-state.mjs
pnpm lint && pnpm format:check
```

**Will not run:** `test`, `a11y`, `contrast`, `content`, `e2e`, `color-golden`, `cvd`, `perf` —
no source, content or screen changes. `build` is run because the manifest this reads is its
output.

## Risks and open questions

- **No `OQ-*`.**
- **The honest limit is the whole of criterion 3, and it is the thing most likely to be
  misread.** A green result here does **not** mean the shipped APK holds only these permissions.
  Three permissions in the real artefact appear in no file this reads. The check says so on every
  run, in its header, and in `gates.json` if it earns an entry — and gate 16 stays exactly as it
  is, because a check that let anybody believe otherwise would be worse than no check.
- **This is not a new gate**, and calling it one would be the same misreading. It is a `ci.yml`
  step in gate 2's neighbourhood — the same place the Android-minimum proof sits — and the
  mirror is what keeps it from being deleted quietly.

## Out of scope

- **Reading a library manifest.** They are inside AARs in the Gradle cache; resolving them needs
  Gradle, which needs a JDK this machine does not have. Gate 16 is the answer and it exists.
- **iOS.** `Info.plist` usage strings are a different shape and a different requirement, and no
  criterion here names them.
- **Changing gate 16, or its expected list.** One security-relevant list, one owner.
