## Intent

Irodora has **one editor**. The content gate requires author ≠ reviewer, so no entry can be
published, so the corpus is empty, so F-012 is blocked and with it F-018, F-019, F-020, F-021
and F-023 — the entire R2 user interface. Five features wait on one person not existing.

The maintainer's decision is to proceed with one reviewer. The question this feature answers
is **how**, and there are two answers with very different consequences.

Dropping the rule is the fast one. It is also the one that makes `verifiedBy` a lie: the field
would keep naming a reviewer, the schema would keep implying independent review, and nothing
anywhere would record that the author checked their own work. Golden rule 12 says never ship a
colour value without its provenance; an entry claiming a review that did not happen is worse
than one claiming nothing.

So: **`independent` stays the default and stays enforced, and `self` becomes a value the entry
has to state.** A self-reviewed entry is publishable and honestly labelled. Nothing is
silently downgraded, and the day a second editor exists, the stricter path is already the one
in use.

## Approach

**Reused.** `checkEditorialIdentity` keeps all four of its existing failures — unknown id, same
id, two ids one person, missing role — and gains a branch rather than a replacement. Fixtures
are generated by [`build-corpus-fixtures.mjs`](../../scripts/build-corpus-fixtures.mjs), so the
twenty-odd invalid corpora regenerate rather than being hand-edited.

**New.** One field on `RecordProvenance`:

```ts
readonly reviewIndependence: 'independent' | 'self' | null;
```

- **`null` before review completes**, exactly like `verifiedBy` and `verifiedAt`, and rejected
  if set at `draft` or `review`. It reuses `requireReviewField`, so the rule is one rule.
- **Required at `verified`, `published` and `superseded`.** Not defaulted. A field that
  defaults to `independent` when absent would let every existing entry claim independence by
  saying nothing, which is the failure this feature exists to prevent.
- **`independent`** → the current rules, unchanged.
- **`self`** → `authoredBy` must EQUAL `verifiedBy`. Declaring `self` with two different ids is
  a failure too: mislabelling in the generous direction is still mislabelling, and it would let
  a genuinely independent review be recorded as a weaker claim than it was.
- **The reviewer's `reviewer` role and `active` flag are still checked under `self`.** Being
  your own reviewer does not exempt you from being a reviewer.

**Increments.** Each leaves the build green.

1. The type, the parser and the workflow branch, with unit tests in `@irodora/corpus`.
2. Fixtures regenerate; two new invalid corpora — `self-review-undeclared` and
   `self-review-claimed-by-two-people` — and the valid corpus gains a self-reviewed entry so
   the accepting path is exercised rather than only the rejecting one.
3. `verify-content-proof.mjs` gains the two cases and is watched going red on each.
4. Spec, ADR, `editors.json` commentary, OQ-5 closed, F-012 unblocked.

## Anticipated effects

| Change | Dependents | Guard |
|---|---|---|
| `RecordProvenance` gains a required field | every authored entry, every fixture, the published bundle format | the parser rejects absence at reviewed statuses; gate 11 over 20+ fixture corpora |
| `checkEditorialIdentity` signature changes | `corpus.ts`, the package's public API, `workflow.test.ts` | typecheck; it is exported from `index.ts`, so a caller cannot miss it |
| An entry can now be published with one editor | the product's provenance claim | **the honest part is the label, not the check** — F-018 must render it, and that is attested, not gated |

**No new effect-graph link.** This tightens an existing contract rather than creating a
dependency: `E-016`'s entry-schema link already covers "the schema is a contract with every
authored file", and this is a change *to* that schema, not a new edge.

## Test plan

- **Unit:** `self` with matching ids passes; `self` with differing ids throws naming both;
  `independent` with matching ids still throws the original message; an inactive or
  non-reviewer identity still throws under `self`.
- **Parser:** the field is rejected when set at `draft`; required at `published`; an
  unrecognised value is rejected rather than coerced.
- **Negative, with decoys —** two new fixture corpora, and the gate must name the right field:
  - `self-review-undeclared`: author == reviewer, `reviewIndependence: "independent"`. This is
    the case that must keep failing, because it is exactly what dropping the rule would have
    allowed silently.
  - `self-review-claimed-by-two-people`: two distinct editors, `reviewIndependence: "self"`.
- **Must stay GREEN:** the valid corpus, which now contains **one self-reviewed entry and one
  independently reviewed entry**. A proof where the new path is only ever red would not show
  that publication actually works with one editor — which is the entire point of the feature.

## Risks and open questions

- **This weakens a real control, and no gate can compensate.** Author-reviewed content is
  content one person checked. The mechanism makes that *visible*; it does not make it
  equivalent. The ADR says so in those words.
- **F-018 must render it.** If the surface does not show that an entry was self-reviewed, the
  honesty is confined to a JSON field nobody reads and the feature has bought nothing. That is
  an attested obligation on this feature, discharged by F-018.
- **OQ-5 closes as a decision, not as an answer.** A Japanese editorial reviewer is still
  wanted; recruiting one is out of scope and the ADR records what changes when it happens.

## Out of scope

- **Writing corpus entries.** F-012 owns the seed corpus; this only unblocks it.
- **A second editor.** Adding one is a roster edit and needs no code.
- **Rendering the label.** F-018.
- **Retrofitting a review workflow with stored prior state.** F-062, unchanged.
